## Part 1 · 为什么做

### S4 · 行业痛点
今天的 AI 编程工具,都是"单人副驾":

- 🧠 **失忆**——会话级记忆,项目上下文反复重讲。
- 👤 **单兵**——真实交付是 BA→开发→测试→PM 接力,工具只模拟一个助理。
- 📉 **知识蒸发**——人一走,项目上下文归零。
- 🚪 **不敢放权**——无人工关卡、无审计、无权限边界,企业不敢上生产。

> 一句话:**AI 很聪明,但它不是你团队的一员。**

---

### S5 · 为什么是现在(Why Now)
**AI 能力够了,缺的是"协作的组织形态"。**

- 模型能力已到可委派复杂任务的拐点,落地却卡在 **协作 / 隔离 / 可控** 三道墙。
- 竞品在卷"写得更快",没人解决"团队怎么一起干、上下文怎么不丢、老板怎么放心"。
- 企业要的不是更强的工具,是一个 **可信、可隔离、有记忆的数字团队**。

---

### S6 · 目标场景与用户
**先打"既要效率、又要可控、还要数据不出门"的组织。**

- 中小研发团队 / 创新部门:用 AI 团队放大交付。
- 外包 / 乙方:以小博大,放大交付产能。
- 知识密集 / 强合规组织:私有化 + 数据主权刚需。

> 目标量级(刻意):数十人 / 上百项目 / 单机 —— 见 S26。

## Part 2 · 产品与差异化

### S7 · 产品形态:群组 = 数字团队
```
[真人 PM]  @小白(BA)  @小明(开发)  @小红(测试)
   └──────── 同一个群 · 同一份上下文 ────────┘
         共享看板 BOARD.md(任务状态的唯一真相)
      每群:独立数据库 · 独立记忆 · 独立 Bot
```

- **群间完全隔离**:一个群一个项目,数据永不串。
- **状态写在文件里**:任务看板人类可读、可审计、重启不丢。

---

### S8 · 核心场景:人在环的交付流水线(招牌能力)
**全自动的效率 + 人把关的可控,二者兼得。**
```
 需求澄清(BA)──门①──► 开发(Dev)──门②──► 测试(QA)──门③──► 交付
                ↑人确认          ↑人确认         ↑人确认 / 打回返工
```

- 每个阶段 AI 自动干活,**关键节点停下来等人点"确认"** 才推进。
- QA 不通过可一键 **打回 Dev 返工**,全程留痕。
- 这就是 **Human-in-the-Loop 治理:AI 提速,人类掌舵。**
- **效率主张**:把传统**周级**交付压缩到智能体流水线的**小时级**(目标 / 示意,视任务复杂度)。

> 内部强调:门的推进现在由 **结构化工具信号驱动**(R1 已通电),确定、可审计、不漂移。

---

### S9 · 能力体系:四层 Skill + 自进化闭环(招牌能力)
**Bot 的能力不是写死的——分层装配,还能自己长出来;但长出来必须人批。**

**双轨装配**:**Traits(内功)** = 被动常驻规范,勾选即缝进 Prompt;**Skills(招式)** = 主动多步工作流,**懒加载**(只提示名称、调用才读全文 → 可拥成百技能而不撑爆上下文)。

**四层 Skill 级联**(覆盖优先级:个性 > 自学 > 角色 > 群组 > 系统)
| 层 | 来源 | 内容 |
|---|---|---|
| **L1 系统** | 平台内置 | 全员通用能力(读写 / 搜索 / 建技能) |
| **L2 群组** | 用户 / Bot | 项目专有 SOP(环境、测试、发布、API 约定) |
| **L3 角色** | 建 Bot 时按 role 自动装配 | 岗位能力(Dev→code-review、PM→write-spec、QA→test-plan) |
| **L4 自学** | **Bot 自己总结** | **从每日处理日志沉淀的项目规律 / 团队偏好** |

**🌟 L4 自进化闭环**(融合 规则提取 + 反思错题本 + 人类审批 三范式)
```
Bot 解决复杂报错 / 发现可复用规律
   → 自动写 learned/draft/(带 evidence 证据链,引用落盘的大日志)
   → WebSocket 弹审批卡(对比"证据 + 经验规约")
   → 人 Approve → 移入 learned/active/ 才生效
```
- **防自我污染**:draft / active 物理隔离,**AI 不能自己让自己的新技能生效——必须人批**。
- **可审计**:每条自学技能都带证据链(从哪条日志学来的),可追溯。

> 这一页同时打三个点:**能力可积木装配** + **自进化但可治理**(回扣护城河② HITL)+ **知识沉淀成资产**(回扣护城河③ 知识资产化)。

---

### S10 · 产品能力 · 离开复盘 Recap(回来秒懂,不掉线)
**痛点切口**:AI 团队 7×24 干活,你离开一会儿,回来一脸懵——发生了什么?决策记哪了?

- **离开复盘(Away Recap)**:你离开期间群里发生了什么,回来一张卡片秒懂;可一键 dismiss,刷新不丢。
- **自动复盘报告(Retro)**:每轮交付结束自动生成 run 报告——**设计决策、技术债自动归档** 进 `retros/`,刷新 `RETRO_LATEST.md`。
- **事件驱动**:工作流暂停 / 完成自动触发,不用人手点。

> 价值:项目进展、决策、技术债不靠人脑记;**交接、审计、复盘有据可查** —— 直接打"知识蒸发"那个痛点。

*(视觉:回到群里弹出的 recap 卡片 mock)*

---

### S11 · 产品能力 · 智能建议 Smart-Compose(下一步说啥,它替你想)
**痛点切口**:面对一群 AI 同事,人最大的负担不是干活,是"我现在该让谁干啥、怎么说"。

- 基于最近对话 + 执行历史,实时生成 **2–3 条"下一步可发给 Bot"的自然语言草稿**。
- 每条都 **@ 真实 Bot、具体可执行、带安全护栏**(绝不生成 `/confirm`、`/abort` 等系统命令)。
- 带缓存,即时返回,不卡顿。

> 价值:把"人驾驶 AI 团队"的认知成本降到最低。
> **S8 的人确认门给你控制权,Recap + Smart-Compose 让这份控制权毫不费力**(理解过去 + 驱动未来)。

*(视觉:输入框上方浮出 2–3 条可点击草稿)*

### S12 · 协作与接入能力(还有这些底座能力)
**除了招牌能力,这些"协作 / 接入"底座让平台真的能落到团队里。**

- **🖼️ 多模态输入**:Bot 看得懂图——截图、报错图、UI 稿直接发群里,Bot 理解后干活(`build_image_content`,已覆盖测试)。
- **🤖 子 Agent 并行委派**:Bot 可派生子 Agent 拆分 / 并行子任务,且 **权限自动衰减**(bypass 不向下传播、高危 allow 被 drop)—— 既放大产能,又不放大风险。
- **👁️ 共享工作区全员同视图**:每个 Bot 启动 / 上下文重注入时,**无条件看到共享工作区目录树 + BOARD / SPEC / PROJECTS** —— 杜绝"选择性失明",协作有共同事实底座。
- **⌨️ Headless / CI-CD 自动化**:命令行无人值守跑任务,标准化 exit code + `--resume` 断点续跑 —— 可接进 CI/CD 管线、定时任务、脚本化批处理。

> 价值:多模态降沟通成本 · 子 Agent 放大产能 · 共享视图保协作一致 · Headless 让它进得了工程流水线。

## Part 3 · 架构护城河

### S15 · 架构总览(进程拓扑)
```
main(FastAPI / WS 入口)
  └── Supervisor(路由 / 中继)
        ├── Worker × N(AI 推理循环,按群分片)
        └── MCP Collector(唯一持 MCP 连接的进程)
```

> 分层契约:**编排(决策)/ 执行(副作用)/ glue 三层物理切分** —— 这是地基级资产。

---

### S16 · 护城河①:蜂窝物理隔离(Cellular Isolation · 企业级地基)
**一个群一个项目(Project-Cell),从数据到进程,物理隔离。**

- 每群独立 SQLite 库 + 独立向量记忆 + 独立 Bot 与权限;**物理文件隔离 = 天然无锁**,杜绝跨项目库锁死(sqlite locked)与数据泄漏。
- 进程级隔离:一个项目崩溃,不波及其他项目(高可用)。
- **内存性价比**:LRU 驱逐——超 **30 分钟**不活跃的项目状态自动持久化并释放内存,新消息到达 **秒级 Rehydrate 唤醒**,超低 TCO。

> 商业价值:**满足企业数据合规与项目保密** + 极低托管成本,可放心给多客户 / 多团队同时用。

---

### S17 · 护城河②:可信与治理(企业敢用的关键)
**纵深安全,让 AI 进得了生产环境。**

- **人确认门**:写操作、关键推进需人工审批。
- **双层命令防护** + **密钥自动脱敏** + **子 Agent 权限衰减**。
- **确定性控制平面(Schema-First)**:工作流推进由**结构化工具调用**驱动(`signal_stage_done` / `signal_rework`)而非 raw text 正则,可审计、不随模型温度漂移;并保留哨兵 fallback 兜底(诚实表述:确定性优先,不吹"100%")。

> 商业价值:把"不敢放权"变成"放权也安心" —— 这是 to B 落地的入场券。

---

### S18 · 护城河③:知识资产化 · 记忆复利(越用越懂你的项目)
**把"交付沉淀成资产"做成护城河——Bot 不是用完即弃,是会成长的数字员工,而且记得"干净、可信"。**

> 知识资产化的两半:**显性一半 = S10 离开复盘 Recap(人读)**;**隐性一半 = 记忆(机器读)**,即下面这套。合起来,系统一边干活一边把知识变成可复用资产。

- **生成式记忆架构**:对话 → 事实抽取 → 反思固化(episodic→semantic),不是简单存聊天记录。
- **三因子加权混合检索**(重要性 + 时近性 + 相关性)+ 关键词增强,取回最该用的那一条。
- **时间衰减 + TTL + 冲突消解**:过时的、矛盾的自动退场,记忆不腐烂。
- **A-MEM 来源链 + 群隔离 + 写入脱敏**:每条记忆可追溯出处、按群隔离、PII/密钥进库前先脱敏。

> 商业价值:用得越久,Bot 越懂这个项目,迁移成本越高 —— **知识资产化的复利型护城河,不是一次性功能。**
> ⤵ 它的工业级架构细节见下一页 **S19(记忆系统技术深潜)**。

---

### S19 · 记忆系统:工业级认知记忆架构(技术深潜)
**不是 RAG 套壳——是工程化落地的"生成式 Agent 记忆"完整范式,三链路全部跑在群物理隔离之上。**

```
① 写入提取  对话 → 抽取原子事实(LLM,带 salience 0~1) → 冲突消解(批量 Top3,
            防幻觉只删候选内 ID) → 写入(自动脱敏 + scored_by_model)
② 周期反思  水位线增量取新事实 → 闸门(条数 & Σsalience) → LLM 提炼高阶洞察
            → 写回(A-MEM 溯源链 source_ids) → 推进水位线 / 积压强制截断
③ 检索装配  Query 重写 → 向量召回(bot+group 硬隔离) → 相似度门槛
            → 三因子加权精排 → Top-K + 历史摘要 → 注入上下文
```

**证明"工业级"的信号(都是做了很久才有的):**
- **三因子加权混合排序**:`0.5·相似 + 0.3·时近(7 天半衰期指数衰减) + 0.2·重要性 + 关键词增强 + 反思特权`。
- **防污染 / 防幻觉**:冲突消解只删"检索候选集内"的 ID(防 LLM 捏造 ID 误删);写入前自动脱敏 PII / 密钥。
- **反思即压缩**:水位线增量 + 积压强制推进,杜绝长尾内存膨胀;反思带 **A-MEM 溯源链**,可追溯"这条洞察从哪些事实来"。
- **可重标定**:`scored_by_model` 记录打分模型来源,换模型时可按来源归一化旧刻度,不污染检索。
- **物理隔离**:`group_id/bot_id` metadata 硬过滤 + 动态多库路由(monolithic / split-DB)。

**对标学术 SOTA(我们做了工程化落地):**
Generative Agents(salience + reflection)· A-MEM(溯源记忆网络)· Reflexion(反思错题本)· MemGPT(分层记忆)

> 一句话:**别人的"记忆"是把聊天记录塞回 prompt;我们的记忆会打分、会消解冲突、会反思固化、会随时间遗忘、还能追溯来源——这是工业级认知记忆,不是 RAG。**

*(视觉:三链路横向流程图;或一张"事实 → 反思 → 溯源树"的 A-MEM 网络图)*

### S20 · 护城河④:工程可靠性 · 底层工程底座(被低估的硬实力)
**架构为长期演进而设计——而且本周刚把"底座"夯到工业级。**

**架构底子**
- 编排 / 执行分层 → 敏捷迭代不塌架;单机零外部依赖(No Redis / 中间件)→ 私有化友好。
- 多进程自愈 + 崩溃恢复 + 完整测试覆盖(116+ 测试文件)。

**本周底层能力上台阶(工业级硬化)**
- **韧性 LLM 调用(优雅降级)**:**限流感知重试**——优先遵从服务端 `Retry-After`、无则指数退避;**流式 at-most-once**——已向消费者吐出 token 后任何异常不再重试,杜绝 token 重复拼装污染;异常按 `isinstance(AIError)` 精确分类(不把含 "AI/LLM" 字样的系统异常误判为模型不可用);持续失败则自动暂停工作流。
- **去竞争化启动 / 混沌复原力**:剔除硬编码 `sleep`,改 SQLite 锁感知指数退避(≤15 次)优雅等主库就绪解锁;崩溃后**只重放幂等工具**(`is_idempotent`,名单经环境变量跨进程传递),真 `SIGKILL` 杀进程测试验证重放无副作用重复(`test_chaos_recovery`)。
- **K8s 级健康探针**:`liveness` 只看快速本地态(不被 DB 锁抖动误杀);`readiness` 用 **`INSERT OR REPLACE` 单行覆盖写**校验库可写(防高频探针撑爆 WAL)+ 校验 Worker 心跳**新鲜度(45s 门限)**与 MCP collector 状态,作为流量准入门;配 LRU eviction + 日志/工作区清理,长跑不 OOM / 不膨胀。
- **工业级代码编辑原语(L0–L3)**:等价类唯一性、块锚点 + 缩进重整、幂等恢复、批量原子、hashline 抗行漂移 —— Dev Bot 改真实大文件稳、准、不被输出长度截断。
- **运维就绪**:systemd 单元(`CPUQuota` + `MemoryMax=4G` 资源隔离,防单 Worker 侵占主机)+ **`sqlite3 .backup` 在线 WAL 零停机热备** + 灾备恢复 runbook。

> 商业价值:**低 TCO、易私有化、可长期演进 —— 而且崩得起、修得回、查得到。**

### S21 · 护城河⑤:异构大模型混合编排
**Heterogeneous LLM Orchestration —— 在同一个隔离群组内,给每个角色配上最适合它的底座模型。**

> 同一个项目群组内,可运行"异构大模型混合编排":Dev Bot 跑代码生成更强的 **Claude Sonnet 4.6 / Opus 4.8**,QA Bot 跑逻辑验证更稳的 **GPT-4o**,PM / BA Bot 选用性价比高、长上下文的 **DeepSeek V3**。它们各自依托最适合的底座,在同一个隔离群组内协同工作。
>
> **以上仅为示例 —— 角色与模型的映射是可适配配置,运营者按需自由编排,随新模型 / 价格变化随时重映射。**

**为什么是护城河,不只是功能:**

- 🎯 **质量最优**:专岗专模,不让全队迁就一个万能模型的短板。
- 💰 **成本最优**:贵模型只用在刀刃上,廉价长上下文模型扛重读场景——同一条流水线同时压成本、提质量。
- 🔓 **零厂商绑定**:不被单一厂商锁死。某家涨价 / 降智 / 限流 / 被封——**只换那一个角色的底座,全队不动、零改代码**。
- ⚙️ **策略可适配**:角色→模型是配置项,不是硬编码;新模型出来,改个配置就换装。
- 🧩 **架构已支持**:provider 抽象层 + 每 Bot 独立模型配置,已接入 7+ 家(Anthropic / OpenAI / DeepSeek / Ollama / MiniMax / GLM / Qwen)。

> 一句话:**别人是"选一个最强的模型",我们是"给每个岗位配一个最合适的模型,而且随时可换"——这是单模型产品在架构上学不来的。**
