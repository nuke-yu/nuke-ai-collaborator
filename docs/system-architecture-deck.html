ipc & bus · 09 / 27
data plane · CELL-18

The worker owns the group DB.

A group's SQLite DB is opened only by the worker holding its lease — the Supervisor never touches it directly.

QUERY / MUTATE proxy

Group-domain reads (history, reactions) & writes (reactions / pins / edits / deletes) go downstream; the owning worker hits the DB and replies via a correlated query_result bus event. Only central data stays supervisor-side.

Lease handoff

To move a group between workers (the routing rebalance), the Supervisor sends RELEASE_LEASE, waits for the LEASE_RELEASED ACK (state flushed + lock released), then re-routes — no split-brain on group.lock.

redaction · 16 / 27
derive_subagent_ruleset

Permissions decay downward.

When a bot spawns a sub-agent, authority can only shrink — never grow.

  • bypassPermissions never propagates — a privileged parent can't hand a blank check to a child.
  • Blanket high-risk allow rules are dropped — sub-agents re-confront the HIL gate for dangerous actions.
  • Sub-agents can't prompt — an ask they'd trigger resolves as denied rather than hanging.

MCP & Sandbox

One connection owner. Mount-isolated execution.

part 03 · 18 / 27
runtime/mcp_collector.py

Why MCP lives in one process.

An MCP connection's anyio cancel scope is bound to its creating task — so all connections live in one Collector, never re-spawned per worker.

Trust boundary: permission is decided on the worker; the Collector only runs pre-authorized calls. OAuth via MCP_AUTH_START; shutdown sweeps orphaned npx/node.

shell_backend.py · container_sandbox.py

Isolation by mount.

_handle_run_shell builds a normalized request and hands it to a backend that decides isolation strength.

LocalShellBackend

Host subprocess, no cross-group isolation — dev only.

ContainerShellBackend

One long-lived sleep infinity Docker container per active group; the worker docker execs in. Only that group's workspace is bind-mounted — siblings / central DB / host secrets are absent. Gated by NUKE_SHELL_EXEC_BACKEND=container.

Deliberately single-machine.

The target is ≤ 30 people and ~100 projects. Single-machine + process isolation isn't a scaling shortcut — it's the optimal design for that envelope.
