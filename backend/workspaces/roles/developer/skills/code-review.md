# Code Review

## 检查维度

1. **逻辑正确性** — 是否存在边界条件遗漏、逻辑错误、空指针风险
2. **代码规范** — 命名是否语义清晰，是否遵循项目约定风格
3. **安全性** — 是否存在 SQL 注入、XSS、不安全的输入处理
4. **性能** — 是否有不必要的循环嵌套、重复计算、N+1 查询
5. **可维护性** — 函数是否过长，是否有重复逻辑应提取为公共方法
6. **测试覆盖** — 关键路径是否有对应测试

## 输出格式

```
## Code Review — <文件名>

### 🔴 必须修改
- [行号] 问题描述 → 修改建议

### 🟡 建议优化
- [行号] 问题描述 → 修改建议

### ✅ 做得好的地方
- ...

### 总体评价
...
```

## 步骤

1. 读取目标文件（或接收粘贴代码）
2. 逐维度检查，记录问题和行号
3. 按优先级分级输出：🔴 必须修改 / 🟡 建议优化 / ✅ 亮点
4. 给出总体评价和下一步建议
