# Write Spec

## 规格文档结构

1. **背景与目标** — 为什么做这个功能，解决什么问题
2. **用户角色** — 涉及哪些用户类型，各自的诉求
3. **功能说明** — 详细的功能描述，含操作流程
4. **边界与约束** — 不做什么，有哪些限制
5. **非功能需求** — 性能、安全、兼容性要求
6. **验收标准** — 如何验证功能完成

## 编写原则

- 每条需求用"系统应该..."或"用户可以..."句式，避免歧义
- 包含正常流程和异常流程
- UI 交互用文字描述，不依赖原型图
- 数据字段明确类型、长度、是否必填

## 步骤

1. 收集背景信息
2. 梳理用户角色和使用场景
3. 按功能模块逐一描述
4. 补充边界条件和异常处理
5. 添加验收标准

## 输出格式

按以上结构输出完整文档，使用 Markdown 格式，各章节用二级标题分隔。
