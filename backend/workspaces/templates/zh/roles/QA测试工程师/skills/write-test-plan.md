# Write Test Plan

## 测试计划结构

1. **测试范围** — 包含哪些功能，明确排除哪些
2. **测试策略** — 各测试类型的覆盖方案（功能/性能/安全/兼容性）
3. **进入/退出条件** — 何时开始测试，何时可以发布
4. **风险与缓解** — 主要风险点和应对方案
5. **资源与排期** — 人力、环境、时间安排

## 测试类型覆盖

| 类型 | 覆盖方法 | 工具 |
|------|----------|------|
| 功能测试 | 手工执行用例 | 测试管理工具 |
| 接口测试 | 自动化脚本 | Postman / pytest |
| 性能测试 | 压测脚本 | JMeter / k6 |
| 安全测试 | OWASP Top 10 checklist | Burp Suite |
| 兼容性测试 | 多端/多浏览器 | BrowserStack |

## 步骤

1. 分析版本变更范围
2. 评估测试重点和风险
3. 确定各类型测试的投入比例
4. 制定排期和里程碑

## 输出格式

按以上结构输出，使用 Markdown 表格和列表，各节用二级标题分隔。
