# Design Architecture

## 架构设计框架

### 1. 需求澄清
- 功能需求：核心业务流程是什么？
- 非功能需求：QPS / 延迟 / 可用性 / 数据量级？
- 约束条件：团队规模 / 技术栈偏好 / 时间窗口？

### 2. 架构决策
- **分层**：展示层 / 业务层 / 数据层 / 基础设施
- **拆分维度**：按业务域 / 按流量特征 / 按变化频率
- **数据存储**：关系型 / 文档型 / 缓存 / 搜索引擎

### 3. 关键设计点
- **高可用**：多副本 / 故障转移 / 熔断降级
- **可扩展**：水平扩展点在哪里？状态如何管理？
- **一致性**：强一致 vs 最终一致，选择依据是什么？

### 4. 方案对比
每个方案说明：优点 / 缺点 / 适用场景
