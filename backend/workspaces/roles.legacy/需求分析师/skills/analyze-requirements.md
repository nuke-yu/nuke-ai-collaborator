# Analyze Requirements

## 分析维度

1. **完整性** — 是否覆盖了所有用户角色和业务场景
2. **明确性** — 有无歧义词（"尽快"、"适当"、"部分"）
3. **一致性** — 需求之间是否存在矛盾
4. **可行性** — 技术或资源上是否可实现
5. **可验证性** — 每条需求是否可以被测试验证

## 步骤

1. 通读全部需求
2. 标注每条需求的问题类型（模糊/遗漏/冲突/不可验证）
3. 整理澄清问题列表
4. 识别核心业务流程，绘制流程概述
5. 提出需求优先级建议

## 输出格式

```
### 需求分析报告

**核心业务流程**
[1-3句话描述主流程]

**问题清单**
| # | 需求位置 | 问题类型 | 问题描述 | 建议 |
|---|----------|----------|----------|------|

**遗漏场景**
- 未覆盖的用户角色：...
- 未覆盖的边界场景：...

**优先级建议**
- P0（核心）：...
- P1（重要）：...
- P2（可延后）：...
```
