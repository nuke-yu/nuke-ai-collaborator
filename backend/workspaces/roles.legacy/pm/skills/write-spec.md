# Write Spec

## 需求文档结构

```markdown
# 功能名称

**状态：** 草稿 / 评审中 / 已确认  
**负责人：** ...  
**目标上线：** YYYY-MM-DD

---

## 一、背景与目标
为什么要做这个功能？解决了什么问题？

## 二、用户故事
作为 [用户角色]，我希望 [功能]，以便 [价值]。

## 三、功能详情

### 3.1 核心流程
（文字描述 + 流程图）

### 3.2 边界条件
- 什么情况下功能不可用？
- 异常处理方式？

### 3.3 非功能需求
- 性能指标：...
- 安全要求：...

## 四、验收标准
- [ ] 条件 A
- [ ] 条件 B

## 五、排除在外（Out of Scope）
本次不做的部分，避免范围蔓延。
```

## 步骤

1. 与用户确认需求背景和核心价值
2. 澄清模糊点（谁用？什么场景？成功标准是什么？）
3. 按模板生成需求文档草稿
4. 写入群组工作区 `SPEC.md` 或指定文件
5. 请用户确认是否需要细化某一部分

## 注意事项

- Out of Scope 一节必写，防止需求蔓延
- 验收标准要可测量、可验证，避免"系统运行稳定"这类模糊描述
