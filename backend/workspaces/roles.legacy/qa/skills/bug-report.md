# Bug Report

## Bug Report 模板

```markdown
# Bug: <标题>

**严重级别：** 🔴 Critical / 🟠 High / 🟡 Medium / 🟢 Low  
**发现日期：** YYYY-MM-DD  
**发现环境：** 开发 / Staging / 生产  
**状态：** 待确认 / 已确认 / 修复中 / 已修复 / 已关闭

---

## 问题描述
（一句话说清楚：在什么情况下，什么功能，出现了什么错误）

## 复现步骤
1. 打开页面 ...
2. 点击 ...
3. 输入 ...
4. 观察到：...

## 预期行为
（正常情况下应该是什么结果）

## 实际行为
（出现了什么问题，附截图/日志）

## 影响范围
- 影响用户：所有 / 特定角色 / 特定条件下
- 影响功能：...

## 附件
- 截图：...
- 错误日志：...
- 复现录像：...
```

## 步骤

1. 向用户询问必要信息（若描述不完整）：
   - 在哪个环境发现的？
   - 如何复现？每次都会发生吗？
   - 错误信息或截图是什么？
2. 根据信息填写 Bug Report 模板
3. 评估严重级别（Critical = 阻塞主流程 / High = 主要功能受损）
4. 将 Bug 记录写入工作区或指定文件

## 严重级别判定

| 级别 | 判定标准 |
|------|----------|
| 🔴 Critical | 系统崩溃、数据丢失、安全漏洞、主流程完全无法使用 |
| 🟠 High | 主要功能受损，无可接受的 workaround |
| 🟡 Medium | 功能部分受损，有 workaround |
| 🟢 Low | 界面问题、轻微体验瑕疵 |
