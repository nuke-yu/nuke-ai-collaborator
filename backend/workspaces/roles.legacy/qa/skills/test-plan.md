# Test Plan

## 测试计划结构

```markdown
# 测试计划 · <功能名>

**版本：** vX.Y.Z  
**测试范围：** 新功能 / 变更模块 / 回归范围  
**测试环境：** 开发 / Staging / 生产

---

## 一、测试范围

### 纳入
- ...

### 排除
- ...

## 二、测试用例

### 功能测试
| # | 场景 | 输入 | 预期结果 | 优先级 |
|---|------|------|----------|--------|
| 1 | 正常登录 | 有效用户名+密码 | 跳转首页，token 写入 | P0 |

### 边界测试
| # | 场景 | 输入 | 预期结果 | 优先级 |
|---|------|------|----------|--------|

### 异常测试
| # | 场景 | 输入 | 预期结果 | 优先级 |
|---|------|------|----------|--------|

## 三、回归测试范围
本次变更可能影响的已有功能：
- [ ] 功能 A
- [ ] 功能 B

## 四、自动化覆盖情况
- 已有自动化：...
- 需新增：...

## 五、上线检查清单
- [ ] 所有 P0 用例通过
- [ ] 无新增 P0/P1 级 Bug
- [ ] 回归测试无退化
```

## 步骤

1. 阅读功能需求文档（SPEC.md）或用户描述
2. 识别测试范围：新功能 + 可能受影响的已有功能
3. 按功能/边界/异常三类编写测试用例
4. 标注优先级（P0 必测 / P1 重要 / P2 可选）
5. 生成测试计划文档，写入工作区
