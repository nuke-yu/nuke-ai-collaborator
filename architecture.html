Core Architectural Principles

Supervisor/Worker Multi-Process Sharding

To prevent Python's event loop from blocking during heavy LLM inference loops and continuous file edits, the system decouples WebSocket connections from calculation sandboxes. The Supervisor routes client frames, while isolated Worker sub-processes execute the ReAct loops, exclusively holding database locks to prevent multi-write SQLite operational conflicts.

Adaptive Security Barriers

High-standard safety mechanisms protect the host filesystem. Dynamic shlex tokenized command checkers evaluate command structures, output redactors mask PEM keys or JWT tokens, subagent spawn gates decay authorization limits, and loop-level port interception prevents overlapping runtime server collisions.

Single-Process MCP Collector Proxy

Adhering to the anyio cancel-scope process boundary rule, all standard I/O and remote HTTP/SSE Model Context Protocol connections are managed by a centralized daemon collector. Workers invoke thin proxy providers that route calls over the internal IPC bus, ensuring reliable reconnection states and secure PKCE OAuth authentications.

UNDER DEVELOPMENT

🤖 LLM BASH Intent Classifier (BASH_CLASSIFIER)

Ref: Claude Code

Current Implementation: Applies regex rules and shlex parsing denylists to filter destructive commands before execution.
Limitations: Static patterns cannot prevent inlined evaluations (e.g. Python scripts executing dangerous operations) or runtime variable redirections.
Proposed Improvement: Integrate a quick semantic classifier model to check command intents. Safely whitelist read-only commands (e.g. git log, cat) to run silently, while enforcing human-in-the-loop (HIL) overlays for state-modifying tasks.

🐳 Docker Container Sandbox Execution (Container Sandbox)

Ref: Openclaw

Current Implementation: executes shell commands directly on the host operating system via Python subprocess pipelines.
Limitations: Even with HIL checks, mistakes or malicious patterns (e.g. rm -rf) still present a risk of data loss or filesystem damage.
Proposed Improvement: Leverage local Docker daemons to execute commands inside ephemeral container environments (e.g., Alpine or Ubuntu). Bind only the shared group folder to the container, protecting the host system configuration.

🔘 Granular Authorization Options Menu (Granularity Menu)

Ref: Gsd-2

Current Implementation: When clicking "Always Allow" in the authorization modal, the system defaults to general tool permission approvals, bypassing safety granularities.
Proposed Improvement: Enhance `PermissionRequestModal.jsx` to show granular options (e.g., allow all git commands, allow only git push, or allow only this exact command) and persist rules via arguments glob pattern synthesis.

✍️ Input Parameters Rewriting Hook (Input Rewriting)

Ref: Gsd-2

Current Implementation: The execution hook only returns binary values (block or allow) when verifying arguments.
Proposed Improvement: Extend before-hook contracts to support argument correction. For example, if the LLM attempts to write to an absolute host path (e.g., /etc/hosts), the hook can rewrite the path to the private relative VFS folder automatically instead of blocking.
