✨ 架构亮点 & 设计哲学

📂
多进程 VFS 隔离与锁互斥
每个协作群组配有专有物理工作区与 SQLite DB。由 LifecycleManager 进行热挂载，且通过 `flock` / `msvcrt` 实现物理排他文件锁，杜绝分布式双写引起的 SQLite 数据库锁定（OperationalError）与数据脑裂。
GroupLock VFS Workspace PRAGMA WAL
⚡
队头阻塞防御与并发广播
`WSManager` 对向群组内多个浏览器的广播调用进行了全面优化，采用并发的 `asyncio.gather` 代替原有的串行 `await`，并为单个连接配置独立的发送超时（`WS_SEND_TIMEOUT`），剔除异常死链，防止慢连接或 TCP 半开拖垮全局事件分发。
asyncio.gather WSManager WSClientProxy
🔒
主子线程解耦与事件安全
在 Bot 写入文件时，实际 I/O 操作交由 `asyncio.to_thread` 在独立子线程运行，而事件的生成与广播（如 `CodeCommitted`）剥离到主事件循环的 async 上下文中，确保底层 `asyncio.create_task` 的线程安全性。
to_thread Event Bus CodeCommitted
🛤️
工作流异常哨兵与原子清理
工作流任务执行器 `runner.py` 内置了完备的异常拦截。当 Bot 或外部工具调用失败时，系统捕获异常并抛出醒目的系统错误通知，同时发布 `WorkflowUpdate` 信号并清理当前 Session 的 pending 状态，彻底摆脱系统静默锁死。
runner.py WorkflowUpdate Error Handling
📡
WSRPC 双向消息帧路由
客户端放弃了传统的 HTTP RESTful API（如 `reactions`/`pins`/`messages`），消息读写全部升级为 WSRPC 双向通道，由后端根据 trace_id 进行上下游追踪，并将作者校验及写控制收归服务端。
WSRPC trace_id Query & Mutate
💾
GC 敏感的数据库连接缓存
数据库连接层基于 `weakref.finalize` 进行垃圾回收监听。当 Python 自动销毁失效的 Event Loop 时，连接池会立刻监听到回调并原子擦除无效连接，完全防范了 loop ID 复用导致的不同 Event Loop 数据库访问报错。
weakref.finalize aiosqlite Loop Connection Cache
