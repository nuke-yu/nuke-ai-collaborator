双向消息管道路径  Data Flow Pipeline

1
下行路由 (FastAPI WebSocket) 浏览器消息发至 Supervisor，Supervisor 查路由缓存 `_routing_cache` 确定拥有该 Group 的 Worker ID。
2
IPC 送达与进程隔离激活 Supervisor 通过 IPC 发送 `USER_MESSAGE` 到目标 Worker。Worker 唤醒 `LifecycleManager.hydrate()` 获取专属物理排他锁 `group.lock` 并绑定 DB。
3
本地总线收集 (Wildcard Subscription) AI Agent 运行触发本地 `Event Bus`，Worker 通过 `subscribe_all()` 持续捕获本地所有状态变更事件。
4
上行广播与多端分发 Worker 将事件封装为 `BROADCAST` 帧送回 Supervisor。Supervisor 广播分发给所有在此 Group 挂载的浏览器客户端。

租约转移与安全接管协议  Group Lease Handoff Protocol

1
修改数据库与下发释放指令 Supervisor 更新全局 `groups` 的映射。向正在运行该组的**旧 Worker 1** 写入 `RELEASE_LEASE`。
2
旧工作器本地析构 (Evict) Worker 1 拦截到指令，中止所有在该组的异步 AI 任务，清理内存缓存，释放 `group.lock` 并关闭数据库连接。
3
安全确认与路由转向 Worker 1 返回 `LEASE_RELEASED` 确认。Supervisor 收到 ACK，将内存路由更新并指向**新 Worker 2**。
4
新工作器无缝初始化 (Hydrate) 后续流量到达 Worker 2，Worker 2 加锁并开启数据库，恢复之前中断的工作流和会话，继续执行。
🔒
GroupLock 物理锁互斥
使用 OS 原生锁机制（Windows 下使用 `msvcrt.locking`，Posix 下使用 `fcntl.flock`）对 `group.lock` 施加非阻塞排他锁。这是防范多进程架构下“分裂脑（Split-brain）”同时写库导致 SQLite Lock 的最强物理防线。
flock msvcrt Anti-SplitBrain
📡
并发广播与队头防阻塞
Supervisor 在向单个群组内的多客户端分发消息时，使用并发并发机制，并设置 `SUPERVISOR_SEND_TIMEOUT`。如果单个连接在 5 秒内因网络波动假死，会被立刻淘汰，防止单个慢连接拖垮 IPC upstream 管道。

🚀
Event Loop 耗时防劣化
将 CPU 密集的 AI 模型决策、长上下文压缩（Auto-Compaction）、以及本地文件沙箱执行分配到不同的子进程（Workers）中。主进程 Supervisor 仅做帧交换，从而彻底隔离了 AI 计算负载导致的主网关 Websocket 延迟毛刺。

⚙️
GC 敏感型 weakref finalize
数据库连接池使用 `weakref.finalize` 对 asyncio event loop 进行周期性的垃圾回收监听。一旦某个进程/线程的主 Loop 被销毁，无效连接会自动从连接缓存池中原子擦除，彻底防范了 Loop ID 复用造成的连接混乱报错。
